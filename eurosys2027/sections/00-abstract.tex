\begin{abstract}
We study interactive model serving in which sessions process new input at fixed intervals and retain history across updates.
As conversations grow, their historical key--value (KV) state can exhaust GPU memory while the combined work of admitted sessions still leaves time within each period.
Offloading idle KV to host memory releases capacity, but restoring it when the next update arrives delays computation.
Restoring it earlier also has a cost: the entire destination must be allocated before copying begins, reducing the time for which other sessions can use that space.
We present the design of \systemname, which uses the known timing of periodic updates for \emph{cyclic KV restoration}: evicting part of a session's idle KV and restoring it before the next update.
Where the application permits, \systemname staggers session starts so that one session's eviction can make room for another's restoration.
It plans these restorations around shared transfer bandwidth and available GPU space, aiming to serve more sessions without changing the history each retains.
Our analysis gives a sufficient condition for KV capacity to be exhausted while compute time remains, subject to an execution-time bound for the workload under study.
