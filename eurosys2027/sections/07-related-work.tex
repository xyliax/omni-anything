\section{Related Work}
\label{sec:related}

\paragraph{Scheduling and KV allocation.}
Orca schedules generation at iteration granularity, allowing batch membership to change as requests arrive and finish~\cite{yu2022orca}.
PagedAttention maps logical KV blocks to noncontiguous physical storage, reducing fragmentation and enabling sharing in vLLM~\cite{kwon2023vllm}.
vLLM also supports swapping and recomputation when memory pressure requires preemption.
These techniques improve how active work uses computation and memory.
The residency problem considered here remains when the valid KV retained by periodic sessions exceeds GPU capacity.
\systemname coordinates when that state occupies the GPU between uses; it still needs an execution engine and allocator that use the resulting capacity efficiently.

\paragraph{State recovery during interruptions.}
InferCept manages requests whose generation pauses for interactions with external tools or environments~\cite{abhyankar2024infercept}.
It estimates interruption durations, chooses among preserving, swapping, and recomputing KV, and chunks recovery work to reduce interference with other requests.
This work establishes that idle-state decisions should consider both memory occupancy and recovery cost.
Our setting adds a recurring restoration target and, where permitted, control over session phases.
The design uses these properties to coordinate repeated recovery with the allocation of its destinations.

\paragraph{Combining loading and recomputation.}
Cake prepares cached prefixes by concurrently loading some KV chunks and recomputing others~\cite{jin2025cake}.
Its division follows causal attention costs: recomputation proceeds from earlier positions while loading proceeds from later positions.
The extension in Section~\ref{sec:discussion} builds on this use of computation to supplement loading.
Periodic restoration additionally requires fitting repeated preparation into a shared schedule as retained histories grow.

\paragraph{Latency-constrained serving.}
DistServe separates prefill and decoding onto different GPUs and allocates resources to satisfy time-to-first-token and time-per-output-token objectives~\cite{zhong2024distserve}.
Its design addresses interference between execution stages with different latency requirements.
\systemname instead coordinates retained state across successive periods of an ongoing session, including time when that session performs no computation.
Both designs require evaluating useful service under a latency objective rather than reporting throughput alone.

\paragraph{Periodic interaction and bounded history.}
Metronome studies memory exhaustion in periodic interaction serving and combines an in-engine KV window with deadline-aware admission~\cite{meng2026metronome}.
Its window bounds state by retaining recent tokens and attention sinks.
Its evaluation also uses phase-staggered input streams.
\systemname preserves the history selected by the application and varies its GPU residency through partial eviction and advance restoration.
This trades host capacity and recurring recovery work for GPU capacity.
The approaches therefore make different retention and resource choices; a performance comparison must either hold retained history fixed or report the effect of changing it.
