\section{Related Work}
\label{sec:related}

\paragraph{Periodic interaction serving.}
Metronome studied memory exhaustion in periodic interaction serving and combined an in-engine KV window with deadline-aware admission~\cite{meng2026metronome}.
Its window retains recent tokens and attention sinks, bounding per-session state, and its evaluation used phase-staggered input streams.
\systemname addresses where the application's selected history resides between updates and when missing state returns to the GPU.
Its scheduling decisions couple phases, eviction amounts, and restoration destinations under shared resource constraints.
Residency scheduling can apply to full or bounded histories; comparisons hold the retention policy fixed to separate residency effects from changes in model history.

\paragraph{State recovery during interruptions.}
InferCept managed requests paused by interactions with tools or external environments~\cite{abhyankar2024infercept}.
It estimated interruption durations and selected among preserving, swapping, and discarding KV for later recomputation, with pipelining and chunking to limit interference.
It thus accounted for both idle memory occupancy and recovery cost.
For periodic interaction sessions, planned ticks supply recurring restoration targets, and applications may also permit phase assignment.
\systemname uses those inputs to coordinate repeated recovery and destination allocation across sessions.

\paragraph{Combining loading and recomputation.}
Cake prepared cached prefixes by concurrently loading some KV chunks and recomputing others~\cite{jin2025cake}.
Its schedule rebuilt earlier positions while loading later ones, exploiting the increasing attention cost of later chunks.
This work supports using computation to supplement loading when I/O is limiting.
\systemname's current design schedules H2D recovery across periods; incorporating recomputation into that schedule remains the extension described in Section~\ref{sec:discussion}.

\paragraph{Execution scheduling and KV allocation.}
Orca introduced iteration-level scheduling so that batch membership could change as requests arrived and finished~\cite{yu2022orca}.
PagedAttention mapped logical KV blocks to noncontiguous physical storage, reducing fragmentation and enabling sharing; vLLM also evaluated swapping and recomputation for preempted requests~\cite{kwon2023vllm}.
These techniques provide efficient execution and memory allocation within a serving engine.
\systemname operates across successive uses of retained state, coordinating its residency with future ticks while leaving model execution and batching to the backend.

\paragraph{Latency-constrained serving.}
DistServe separated prefill and decoding onto different GPUs and allocated resources against time-to-first-token and time-per-output-token objectives~\cite{zhong2024distserve}.
It addressed interference between execution stages with different latency requirements.
Our service objective measures completion against recurring session ticks and includes any waiting for retained state.
Both approaches evaluate the load served within a latency objective, which is also the basis of the capacity metric in Section~\ref{sec:methodology}.
