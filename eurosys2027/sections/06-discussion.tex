\section{Discussion and Limitations}
\label{sec:discussion}

The design's benefit depends on how much idle state can be reclaimed and restored within the service budget.
Three conditions limit that opportunity: application timing, maximum-context planning, and the resources available for recovery.

\paragraph{Application timing and phase control.}
An application may expose future ticks while fixing its release phases.
Advance restoration can use those ticks, but phase assignment then provides no additional control over demand.
With different periods or unequal histories, evenly spaced phases also need not produce evenly distributed transfer or compute demand.
Furthermore, a predicted tick does not guarantee that new input arrives on time.
Late input and execution backlog reduce the useful idle interval, and restoring historical KV cannot remove those sources of delay.

\paragraph{Planning at maximum context.}
Sizing session state at the configured context limit allows the schedule to be reused as histories grow.
It can reserve more capacity than currently short sessions need and therefore admit fewer of them.
The context limit bounds retained state; measured completion latency still depends on the workload, batching, and transfer costs.

\paragraph{Resource balance and topology.}
A small retained history leaves little memory to reclaim, and a short interval between uses leaves little time to restore it.
Effective transfer bandwidth, host-copy availability, and batching efficiency determine the useful eviction budget.
When restoration spans multiple devices, the model must track destination capacity on each device and contention along each transfer path, including shared host-memory channels and interconnects.
The effective bandwidth in Equation~\ref{eq:transfer-budget} must reflect that topology; summing nominal per-device bandwidths can overestimate available service.

\paragraph{Future work: recomputation.}
The current residency design restores state through H2D transfers.
A further planning dimension would choose which evicted ranges to reconstruct from retained inputs and which to load from host memory.
This extension would require backend replay support, space for reconstructed KV and temporary work, and compute slack across all admitted sessions.
Recovery would still need to finish before use while preserving the computation budget for normal updates.
The joint transfer and recomputation policy and its evaluation remain future work.
