\section{Introduction}
\label{sec:introduction}

Long-lived interaction sessions expose a serving problem that short-lived
requests hide.  Each update appends a small input chunk, reuses the session's
logical context, and leaves the session open for the next update.
Transformer serving avoids recomputing that history by retaining attention
key/value (KV) state, but every update also extends the state that must be
stored.  When multiple sessions draw from a finite GPU KV pool, their aggregate
working set can exhaust that pool before the computation required in a period
saturates the device.  The resulting challenge is to manage a growing state
working set while preserving complete context and timely service.

Serving at request granularity exposes arrivals, runnable requests, and cache
matches, but does not reveal when an idle session will be used again.  Each
direct policy then pays a different cost.  Keeping every session fully
resident avoids restoration latency but lets the growing KV working set
determine admission.  Discarding state avoids long-term residency but repeats
an increasingly large prefill on the next update.  Reloading state only after
that update is admitted moves the host-to-device transfer onto its service
path and can synchronize restoration traffic across sessions.  CPU offload
alone therefore does not determine which state should remain resident or when
it should return.

We define the studied workload as a \emph{periodic interaction session}: a
long-lived session that appends input at a target period while preserving its
logical context.  Periodicity supplies an expected next-use time and an
intrinsic reuse interval between successive updates.  The system goal is to
use this information to reduce idle-session GPU KV residency while retaining
complete context and preserving a per-period latency target.  This goal is
bounded by three physical budgets: GPU KV capacity, computation within a
period, and host-to-device restoration bandwidth.  No mechanism can admit work
beyond this feasible region, so the system still requires admission control
when the total resource demand exceeds those budgets.

This setting creates three systems challenges.  First, \emph{shaping demand}
must trade lower instantaneous demand against batching efficiency: smaller
batches can repeat weight reads.  Second, \emph{partial residency must
be safe}: the system must distinguish session activity, request ownership,
physical residency, host coverage, and in-flight transfers rather than encode
them in a single ``offloaded'' bit.  Third, \emph{restoration must be timely
without becoming a correctness assumption}: capacity can defer a prefetch,
the next input can overtake it, and cache replacement can evict it before
reuse.

We present \systemname, a next-use-aware residency policy for periodic
interaction sessions.  For the same session, the policy coordinates release,
feature extraction, idle eviction, restoration, and the next admission without
tying correctness to a particular output-delivery path.  Release-offset
scheduling assigns sessions stable positions in an absolute period grid,
spreading their releases without changing their periods (Section~\ref{sec:design}).
Incremental host backing records recoverable KV coverage as context grows, and
the idle transition releases request ownership before evicting selected GPU
tail blocks.  At the next update, retained blocks are matched in the GPU
prefix cache and missing host-backed blocks are loaded on demand.  KV
prefetching starts the same restoration path early enough to overlap input
processing when capacity permits.  A deferred, overtaken, or evicted prefetch
falls back to on-demand reload, while a gap in host coverage falls back to
recomputation.  These fallbacks preserve correctness independently of a
prefetch hit.
