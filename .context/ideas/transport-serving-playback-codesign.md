# 传输–推理–播放联合调度（设想）

未进入事实层；非现行主线。快照日期：2026-08-14。

## 方向

双工语音链路由三段组成：网络传输（上行音频 / 下行音频）、模型推理（serving）、客户端播放。现状是三段各按局部目标孤立优化——传输管自己的 jitter buffer，serving 管自己的队列，播放管自己的缓冲——互不知晓彼此状态。我们的出发点：全双工模型不是「电话另一端的人的替身」，而是实时环路的中间环节，端到端会话质量是传输、推理、播放的联合控制问题。三个协同面：

- **网络感知的推理调度**：gateway 的槽位 / 相位指派与 tick deadline 预算感知帧到达抖动，而不是假设帧准点到达
- **执行感知的传输优先级**：模型执行状态（本 tick 是否临近 deadline、park / 回载是否在途）反馈给传输侧的帧优先级与丢弃策略
- **联合播放控制**：播放缓冲同时吸收网络与模型两个方差源，而不是只按网络 jitter 设计

## 后台参与（本点的特有维度）

双工前台在与用户交互的同时会调用后台模型 / 工具，结果写回对话。链路上的负载因此有刚弹之分：前台 tick 与播放 deadline 是刚性约束；后台调用的发起与结果写回天然容忍延迟，是可自由挪动的弹性负载。联合调度把弹性负载当作调度自由度：前台临近 deadline 或网络退化时，后台写回让路 / 错峰。

## 与现有主线的关系

错开相位 gateway（槽轮 + 绝对网格）已经是 serving 侧的时间轴协议；本点把该时间轴向两端延伸到传输与播放，形成一个联合控制环。实测栈目前网络段是本机回环，构造实验需先引入可控的网络退化注入。

## 未决

- 差异化定位：实时通信与推理服务的交叉近来开始受关注；我们的候选差异点是硬 tick 语义 + 后台注入弹性负载的**双负载**联合调度
- 最小实验形状：网络退化注入器 + 现有 Perfetto 时间线扩展出传输 / 播放段
- 指标候选：tick deadline 违约率、端到端响应延迟、播放卡顿率（网络退化梯度下对比孤立优化基线）
